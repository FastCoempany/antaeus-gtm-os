Everything the room is supposed to offer.

The full contract for the most strictly-specified room in Antaeus — a live discovery operating console the seller runs during a real 30+ minute scheduled call. Not a framework gallery, not a methodology viewer, not a notepad. The room answers whatever the buyer does with control, not density.

5 · Rails & control

The 7 required rails + the on-call control laws

The 7 rails (always reachable)
Framework rail — the current lens, switchable (not a card gallery)
Segment rail — the live spine; one open at a time, jumpable
Recover-the-call rail — authored recover guidance + jump-actions to the segment where the recovery runs
Learned-truth ledger — what's actually been earned, and what's still missing
Worked memory — which nodes have been worked (N of essential)
Next-step docket — forces the room toward a real dated next move
Support dossier — proof + objection + inbound-question pack, reachable mid-call
The 3 compression modes
Off — shows all nodes
Essentials — shows only the must-hit nodes for the framework
Emergency — the rescue state: collapses the spine to the segment you're in and hoists the recover moves to the front
Mandatory control laws
Skip-ahead handlers · tie-back discipline (held vs deploy) · objection + inbound-question handling from the live surface · phase progress & resumption · learned-fact capture close to the live node (never a note graveyard)
The non-negotiable build tests
The seller can: recover from a buyer interruption in one move · switch into compression without losing the next-step path · answer a buyer question without abandoning discovery control · see what-to-say / what-to-listen-for / where-to-go-next without reading paragraphs · resume after being interrupted, challenged, or delayed. And the room always preserves the distinction between earned facts, support proof, and deploy-now language.

8 · Guardrails

Must never be flattened · what it is NOT

  • Never flatten any of the 19 primitives
  • Never flatten the on-call control laws (real compression, skip-ahead, dossier, tie-back)
  • The recover rail must carry authored guidance + its jump-actions
  • The handoff stays outcome-driven
  • Preserve earned-facts vs support-proof vs deploy-now
  • Not a framework gallery / methodology viewer
  • Not a notepad / freeform note graveyard
  • Not a FAQ page or second main canvas
  • No decorative timer, no heat meters / abstract chips
  • No fake branching that all lands the same
  • No dense chrome that competes with the live node
