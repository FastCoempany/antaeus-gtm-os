4. What this room is for and how it works

The room's capability map: its purpose, every part and what it does, what flows in from and out to other rooms, and what it must never become.

Future Autopsy · Diagnosis Table · capability map

Pre-mortem the deal before it dies.

Diagnosis Table (intervention) · named premium asset · settled 2026-07-04 (the countdown)

Pre-mortem the deal before it dies; show the causal pattern and the corrective route. The deal is pinned as evidence on a forensic light-table. The analysis surfaces the causal pattern (e.g. pressure before clarity), the intervention options, and a command row. The positive example the other Diagnosis Table rooms should borrow from.

Sourced from: canon §4.14 + the autopsy generator + deal-health subset (shipped src/future-autopsy). Settled design: future-autopsy-countdown-2026-07-04.html (the decay line).
1 · Purpose

What the room is for

Diagnose failure before it happens. Forensic light-table posture: each at-risk deal is pinned as a case, its causal pattern named, its corrective route made obvious. Never soften into “risk review” — this is consequential route correction, not commentary.
2 · The analysis

What each pinned case shows

ElementWhat it is
The causal patternthe named failure shape — e.g. “pressure before clarity”
Intervention optionschange the 3× deal truth · test the risk-fix lens · rebuild the agenda
The horizon taghow many days out the death is
The command rowRun selected · Urgent autopsy deal · Copy brief
3 · What it offers

The primitives

Capability / surfaceWhat it does
The pinned-case ledgerThe live set of at-risk deals pinned as evidence — count is dynamic, never hardcoded.
The horizon tagDays-out until the deal dies if nothing changes.
The causal-pattern narrativeThe named failure pattern behind the case.
The intervention optionsThe concrete corrective lenses to run.
The command rowRun selected · Urgent autopsy deal · Copy brief.
The route rackBack to Deal Workspace / Discovery Studio / Pilot Desk — the corrective destinations.
4 · Flows

What comes in, what goes out

Flows in
  • deals with pressure/stage truth from Deal Workspace
  • unresolved gaps from Discovery Studio
  • pilot state from Pilot Desk
  • (loss-pattern feedback from Getting to Signed — was it lost in procurement, before anyone argued terms?)
Flows out
  • reroute logic into Deal Workspace · Discovery Studio · Pilot Desk
5 · Guardrails

Must never be flattened · what it is NOT

Must never be flattened
  • Failure-pattern diagnosis
  • Consequential route correction
  • Strategic severity
  • The pinned-as-evidence posture (count dynamic, never hardcoded)
What it is NOT
  • Never soften into “risk review”
  • Not a status dashboard
  • Not a boxed warning-board
  • Not abstract diagnosis without a corrective move
