3. What this room is for and how it works

The room's capability map: its purpose, every part and what it does, what flows in from and out to other rooms, and what it must never become.

Outdoors Events · Live Instrument · capability map

Where people are gathering, found for you.

Live Instrument (live execution) · ADR-015 + ADR-016 · settled 2026-07-07 (proximity + the get-there rail)

A discovery surface that finds offline gatherings relevant to the operator’s product category and surfaces them — the Signal Console pattern applied to events instead of accounts. The system finds; the operator marks, prioritizes, dismisses. Informational, not attributional — no ROI tracking, no deal-attribution. The operator shouldn’t be the one googling for conferences.

Sourced from: canon §4.22 + ADR-016 (discovery reframe, supersedes ADR-015 §3/§6) + ADR-015 (room mind) + the 2026-07-07 get-there utility. Settled design: outdoors-events-icon-rail-2026-07-07.html.
1 · Purpose

What the room is for

Read the workspace’s product category, run web-search-grounded queries for gatherings in that space + adjacent + indirect, and return events with real source URLs and a one-sentence relevance reason. The operator’s attention goes to deciding which events matter, not finding them. This is the Briefing pipeline pattern: workspace context → web search → LLM enrichment → typed rows → voice-gated surfacing.
2 · The relevance tiering

Proximity as the organizing axis

The tiering is felt as distance, not flat labels — an orange→blue→grey gradient on the proximity spine.
TierMeaning
Directyour category — closest in
Adjacentyour buyers — one ring out
Indirecttheir orbit — the outer ring (your ICP might show up)

4 · The get-there boundary

Outbound links + a weather glance only

Once the scout finds a gathering worth the time, the room helps the operator decide and depart — but it hands off to the real sites (Google Flights / hotels / the registration page / an .ics) and never stores or manages an itinerary. Registration is a link out, never registration tooling built in-room. This honors the “never a logistics tracker” rule. New travel/weather/conference line-icons (plane · bed · sun/cloud/rain · lanyard-badge · calendar · pin · ticket) join the brand iconography.
5 · Flows

What comes in, what goes out

On-demand discovery only (no weekly cron, founder direction 2026-06-02). Cost ceiling per workspace; degradation policy (warning 80%, throttle 100% drops adjacent + indirect, pause 150%).
Flows in
  • workspace_profile.product_category (the seed for the query plan)
  • web sources via the Anthropic web_search tool
  • (no reads from other Antaeus rooms in first-ship — category-anchored)
Flows out
  • deferred: Phase 2 — Prospecting Desk handoff (event-tagged contacts → prospects)
  • deferred: Phase 3 — Signal Console attribution + Deal Workspace sourced-from tag
  • a navigation-only chip on the Briefing’s World view (no data flow)
6 · Guardrails

Must never be flattened · what it is NOT

Must never be flattened
  • The discovery posture (the operator does not author events — the system does)
  • The relevance tiering (Direct / Adjacent / Indirect is the organizing axis)
  • The voice gate on every LLM-authored string
  • The audit envelope chain (where did this event come from?)
  • The get-there layer as outbound links + a weather glance, never itinerary management
What it is NOT
  • No deal-attribution
  • No registration tooling built in-room
  • Never an event-aggregator feed
  • Never a CRM screen or a logistics tracker
